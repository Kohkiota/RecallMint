Multi-PDF processing can continue well beyond the pipeline deadline, including after the page limit is already known to be exceeded. This can cause hard platform termination before the intended terminal state and cleanup are recorded.

Full review comments:

- [P1] Stop counting as soon as the page limit is exceeded — /workspaces/RecallMint/app/(app)/app/upload/_lib/upload-pipeline.ts:242-247
  When an early PDF already pushes `totalPages` over `OCR_MAX_PAGES`, this loop still downloads and parses every remaining PDF before checking the limit. With a manifest containing many PDFs, those extra 60-second GETs and PDFium loads can exhaust the invocation deadline, leaving the operation unterminalized instead of reporting `page_limit_exceeded`; check the accumulated count inside the loop and return immediately after destroying the current handle.

- [P1] Enforce the deadline during multi-PDF phases — /workspaces/RecallMint/app/(app)/app/upload/_lib/upload-pipeline.ts:668-683
  The deadline is checked only once before the entire render phase, although the phase can perform up to one 60-second GET plus rasterization per PDF. If at least 60 seconds remain but the aggregate work exceeds the remaining budget, the platform can terminate the invocation before it records `deadline_exceeded` or deletes the source objects; recheck the remaining budget before each PDF and before expensive rasterization work.
