The new side peek can make long card content inaccessible due to an unconstrained scroll area, and it introduces a close path that can drop in-progress option edits. These are functional issues that should be addressed before considering the patch correct.

Full review comments:

- [P2] Constrain the scroll container height — /workspaces/RecallMint/app/(app)/app/exams/[id]/_components/exam-card-side-peek.tsx:90-90
  When a card has enough question/options/explanation content to exceed the viewport, this `overflow-y-auto` div has no constrained height or flex sizing, so it grows with its contents instead of becoming scrollable. Because the parent is a fixed-height dialog, the lower fields can render past the viewport with no usable panel scrollbar; make the content column/flex layout constrain this body area, e.g. `flex h-full flex-col` on the content and `min-h-0 flex-1 overflow-y-auto` on the body.

- [P2] Preserve option edits on dialog unmount — /workspaces/RecallMint/app/(app)/app/exams/[id]/_components/exam-card-side-peek.tsx:138-141
  If the user is editing an option cell and closes the side peek with Esc before the cell blurs, the dialog unmounts `InlineOptionList` and the in-progress `InlineOptionCell` state is discarded because option cells only save on blur and have no commit-on-unmount path. Text fields in this panel explicitly handle unmount commits, so the same close path can silently lose option text/id/explanation edits.
