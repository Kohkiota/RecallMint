The publish flow generally preserves fencing and transactionality, but a prepared operation with a missing payload remains permanently retryable without any state transition. This creates an infinite takeover/retry loop for a representable database state.

Review comment:

- [P2] Terminalize prepared operations with a missing payload — /workspaces/RecallMint/app/(app)/app/upload/_actions/publish-prepared.ts:452-455
  When an operation is `prepared` but `prepared_payload` is null, returning `stale` leaves the row in the same publishable state without releasing its lease or recording a terminal result. Every takeover will encounter the same condition indefinitely, unlike malformed and empty payloads immediately below, which are correctly persisted as `terminal_failed`; handle this as payload corruption through the fenced terminal CAS as well.
