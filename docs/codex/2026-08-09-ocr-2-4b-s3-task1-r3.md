The metadata parser accepts some impossible calendar dates because `Date.parse` normalizes them, violating its fail-closed contract and potentially producing unsafe age calculations.

Review comment:

- [P2] Reject normalized invalid calendar dates — /workspaces/RecallMint/lib/storage/r2.ts:470-474
  When `LastModified` contains a format-valid but impossible date such as `2026-02-30T01:00:00Z`, Node's `Date.parse` normalizes it to March 2 instead of returning `NaN`. This bypasses the intended fail-closed validation and can shift the object's apparent age by days, potentially causing the sweeper to delete an object prematurely; validate that the parsed UTC components round-trip to the supplied calendar fields.
