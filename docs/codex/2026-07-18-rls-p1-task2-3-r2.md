The primary database-role migration and tests work, but two admin-only scripts retain hidden runtime dependencies on the app database URL in their error paths. This causes operational failure records to be dropped under the newly documented configuration.

Full review comments:

- [P2] Keep failure logging on the admin connection — /workspaces/RecallMint/scripts/backfill-clerk-metadata.ts:127-127
  When this non-dry-run backfill encounters a Clerk API error, `syncClerkPublicMetadata()` calls `recordIntegrationFailure()`, which still inserts through `getDb()` and therefore requires `DATABASE_URL_APP`. The script now documents and initializes only `DATABASE_URL_ADMIN`, so its failure ledger insert is silently lost with “DATABASE_URL_APP is not set” precisely when an API failure occurs. Route this script's failure recording through the admin DB or otherwise supply the selected DB explicitly.

- [P2] Avoid falling back to the app URL during GC failures — /workspaces/RecallMint/scripts/gc-image-assets.ts:542-542
  When an object deletion fails, the GC callback invokes `recordIntegrationFailure()`, which uses `getDb()` rather than this admin connection. An operator following the new admin-only configuration will therefore fail to persist the GC failure because `DATABASE_URL_APP` is unset (the helper catches that error and only attempts notification), leaving the failure ledger incomplete. Pass an admin-backed recorder into the GC operation or make the recorder use this connection.
