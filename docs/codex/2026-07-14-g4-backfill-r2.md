The new backfill has correctness/operational issues in its CLI argument handling and unbounded asset lookup that can cause unintended all-user writes or failures on large production datasets.

Full review comments:

- [P2] Reject --user without a user id — /workspaces/RecallMint/scripts/backfill-card-asset-refs.ts:243-246
  When the script is invoked with `--user` but no following value, this parsing leaves `userId` as `undefined`, which is indistinguishable from intentionally running the all-user backfill. In production, a targeted invocation with a missing argument would therefore delete/insert refs for every card instead of failing fast; the CLI should validate that `--user` has a non-flag value.

- [P2] Batch asset lookups to avoid parameter limits — /workspaces/RecallMint/scripts/backfill-card-asset-refs.ts:268-276
  For an all-user backfill with more than PostgreSQL's bind-parameter limit worth of distinct UUID image keys, this single `IN (...)` lookup will expand to too many parameters and the script will fail before writing refs. Since this script is intended to run across the production card table, the candidate IDs should be queried in batches instead of one unbounded `inArray` call.
