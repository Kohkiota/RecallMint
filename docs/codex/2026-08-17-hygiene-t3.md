The new gate detects deletions that occur before each lookup, but it does not close the concurrency window between verification and successful completion. The all-or-nothing property motivating the change can therefore still be violated.

Review comment:

- [P1] Synchronize cleanup with the success gate — /workspaces/RecallMint/lib/media/deck-download.ts:236-238
  When cleanup deletes a blob after `verifyDeckBlobs` checks it but before the job is marked `done`, this path still returns `ok:true` with an incomplete cache. The same race exists in the all-hit path between verification and its return. Since Cache API lookup and the IndexedDB status update are not atomic, an existence check alone cannot provide the stated all-or-nothing guarantee; cleanup and download need a shared lock or another protocol that prevents deletion throughout verification and commit.
