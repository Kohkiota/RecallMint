The normalizer allows option values that the established publish validation rejects, undermining the intended per-card isolation and potentially causing an otherwise valid prepared operation to fail at publication.

Review comment:

- [P1] Reject options that violate publish-time field constraints — /workspaces/RecallMint/lib/ocr/normalize-prepared.ts:55-59
  When Gemini returns an option with an empty `id`, blank/over-1000-character `text`, or over-2000-character `explanation`, this schema accepts it and `normalizePreparedCard` emits it into the prepared payload. The later publish boundary's `optionSchema` rejects those same values, so one malformed card can abort atomic publication instead of being isolated during normalization. Apply the existing option field constraints here or in the hard-invariant checks before minting IDs.
