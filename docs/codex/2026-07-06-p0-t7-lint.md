The new lint boundary is incomplete because it only catches alias-based app imports from lib/components, leaving relative imports into the app layer unguarded.

Review comment:

- [P2] Block relative imports into the app layer — /workspaces/RecallMint/eslint.config.mjs:34-34
  For `lib/` and `components/` files this only restricts alias imports such as `@/app/...`, so the same forbidden dependency can still be introduced with a relative path, e.g. `components/marketing/foo.tsx` importing `../../app/(marketing)/contact/actions`. Because the rule is meant to enforce the layer boundary rather than just alias style, these relative imports will pass lint and bypass the new guard.
