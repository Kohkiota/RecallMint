The main flow is type-safe and generally well tested, but idempotent response ordering is not actually stable for all accepted source IDs because two different collation rules are used.

Review comment:

- [P2] Use the database ordering for the initial response — /workspaces/RecallMint/app/(app)/app/upload/_actions/prepare-upload.ts:379-379
  When `sourceId` contains non-ASCII characters, this JavaScript UTF-16 comparison can produce a different order from PostgreSQL's configured collation used by the replay query's `ORDER BY`. The first response and an idempotent replay can therefore return different `reserved` arrays despite the stated contract; either restrict `sourceId` to an ordering-safe alphabet or construct both responses using the same database ordering.
