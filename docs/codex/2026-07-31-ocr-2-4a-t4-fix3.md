The new concurrency gate is not mutually compatible with the still-present upload path, allowing old and new uploads for the same user to overlap. This breaks the stated single-upload invariant.

Review comment:

- [P1] Include legacy processing uploads in the live-operation gate — /workspaces/RecallMint/app/(app)/app/upload/_actions/prepare-upload.ts:240-248
  When a user already has an upload started through the existing `runUploadGuardTx` flow, that flow creates only a `source_documents(status='processing')` row and no `upload_operations` row. After its transaction releases the advisory lock, this query sees no live operation and allows `prepareUploadTx` to start a second upload concurrently, defeating the existing one-upload-per-user guard during rollout or with older clients. The gate should also account for non-stale processing source documents, or the old flow must create a corresponding operation.
