The source GC eligibility guard is only evaluated during promotion and is vulnerable to a concurrent derivation insertion before collection. This can delete a live source object and cascade-delete provenance.

Review comment:

- [P1] Recheck derivations before deleting source objects — /workspaces/RecallMint/scripts/gc-image-assets.ts:628-636
  If a crop reads a source while it is `ready`, then GC promotes it while the crop is still writing, an `asset_derivations` row can be inserted after the promote query's `NOT EXISTS` check. The collect loop then deletes the R2 source and deletes the parent row, whose cascading FK silently removes the newly committed provenance. Recheck for derivations immediately before the R2 deletion, or otherwise serialize promotion/collection against derivation creation.
