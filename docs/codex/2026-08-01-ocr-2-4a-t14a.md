The stale-source exclusion can retain abandoned operations and processing documents indefinitely, defeating both cleanup and the intended retention cap. The crop deadline can also be overridden through the public Server Action interface.

Full review comments:

- [P1] Reclaim sources blocked by abandoned operations — /workspaces/RecallMint/lib/exams/source-doc-status.ts:110-123
  When an `awaiting_sources`, `claimed`, or `prepared` operation is abandoned, this unconditional `NOT EXISTS` exclusion prevents its stale `source_document` from ever being marked failed. The new seven-day cap is only applied when `claimOperationTx` is called, so an operation receiving no further requests remains nonterminal indefinitely and permanently bypasses this cleanup. Limit the exclusion to operations still within the retention/lease window, or expire old operations as part of reconciliation.

- [P2] Derive the crop deadline on the server — /workspaces/RecallMint/app/(app)/app/upload/_actions/publish-prepared.ts:473-475
  Because this exported function is a Server Action, every argument is client-controlled; `deadlineAt` is therefore not an internal-only injection point. A caller can supply a far-future or invalid date and bypass the crop budget, allowing crop work to continue until the platform timeout. Keep the public action single-argument and inject clocks through a non-exported helper used by tests.
