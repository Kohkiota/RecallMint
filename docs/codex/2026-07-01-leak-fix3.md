## Codex Findings(要点、file:line は Codex 提示)

**根本原因(コード確定)= resize 開始/終了で `<tbody>` 全体が unmount+remount する**
- `TableBody` は通常 component(`exam-card-table.tsx:73`)、`MemoizedTableBody` は `memo(TableBody, ...)` = **別の React element 型**(`:120`)。
- render が `columnSizingInfo.isResizingColumn` で両型を同位置で出し分け(`:524`)→ resize 開始で subtree を破棄して新規 mount、停止で再度。
- その subtree は巨大: 1 行 = InlineTextField×5 + options editor + TagCell(`columns:91/139/155`)。各 TagCell は最大 6 popover root(`tag-cell:37/148/164/184`)。
- **DOM 増加と listener 増加は同一 trigger(1 root)**。per-move 行再レンダーではない(T1 が isResizingColumn 中は止めている)。「mounted body subtree を繰り返し構築・破棄」しているのが増加源。

**app cell 側に cleanup 漏れなし**
- InlineTextField は debounce timer を unmount で clear(`inline-text-field:142`)、ref は `inputRef.current` 代入のみ(`:247`)。InlineOptionCell / CardTagEditFields(rAF cancel `:92`)/ CardTagOptionList も global listener/timer 漏れなし。

**Radix / Floating UI は cleanup path を持つ**
- `radix-ui@^1.4.3`(popover 実体 `@radix-ui/react-popover@1.1.15`)。閉じた popover content は Presence で未 mount(`react-popover/index.mjs:110/119`)。
- 開時のみ: DismissableLayer は document listener を removeEventListener(`dismissable-layer:95/168`)、Presence は animation listener 除去(`presence:97`)、Floating UI `autoUpdate` は scroll/resize listener + ResizeObserver を貼り、cleanup で remove/disconnect(`floating-ui.dom.mjs:622/667`)。
- 上流 leak issue は Dialog/Tabs 中心で、**本 app で Popover content が主 retaining reference である直接証拠は未確定**(= detach 後 GC されない機序は未証明、trigger は remount で確定)。

**Fix 提案(Codex)**
- 同位置の body component 型を 1 つに固定(親 JSX で TableBody↔MemoizedTableBody を swap しない)。`<TableBody table freeze={isResizing}/>` の中で memo 化 body に委譲し、resize 中は columnSizing を無視する comparator。
- cell の mounted popover root 削減: TagCell を 1 popover に集約(trigger state で initialStage/initialCategoryId を決める)→ 最大6/行 → 1/行。
- 行仮想化は churn が mounted 数比例ゆえ leak **rate** を比例低減するが root は直らない(mount 数を下げるだけ)。
