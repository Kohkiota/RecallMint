- [P1] Handle concurrent recovery inserts idempotently — /workspaces/RecallMint/lib/media/crop-and-store.ts:319-328
  When two invocations for the same `figureAssetId` overlap, the PUT loser can observe no asset row before the PUT winner commits its DB transaction, so both proceed here and one fails with a primary-key violation instead of returning `reused`.
