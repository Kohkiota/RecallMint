The visualization fails for an explicitly accepted PDF input type, and valid same-stem inputs can overwrite each other's output. Both cases prevent reliable review of all processed files.

Full review comments:

- [P1] Render PDF inputs in a browser-supported element — /workspaces/RecallMint/scripts/ai/ocr-box2d-viz.ts:40-40
  When the input is a `.pdf`, `loadImageInline` produces an `application/pdf` data URI, but the generated HTML places it in an `<img>` element. Browsers do not render PDFs as images, so the source page is blank and the percentage-based overlays cannot be reviewed. Either rasterize PDF pages before rendering or exclude PDFs from this visualization script.

- [P2] Preserve extensions when deriving output names — /workspaces/RecallMint/scripts/ai/ocr-box2d-viz.ts:198-198
  When the directory contains supported files with the same stem, such as `page.png` and `page.jpg`, both are written to `page.html`; the later file silently overwrites the earlier visualization while `writtenPaths` still records both writes. Include the source extension or another unique component in the output filename.
