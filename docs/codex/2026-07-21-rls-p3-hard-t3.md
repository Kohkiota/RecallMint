- [P1] Preserve envelope-level handling for database initialization failures — /workspaces/RecallMint/app/api/entity-mutations/bulk/route.ts:244-246
  When `getDb()` throws (for example, due to missing configuration or client initialization failure), it now occurs inside this per-mutation `try` and is converted into a `200` response with the mutation listed in `failed`. Previously `getDb()` ran before the loop inside the envelope-level `try`, so the same failure produced the intended retryable `503`; the updated contract test masks this regression by moving the injected failure to an unrelated grouping helper. Acquire/validate the database before entering the per-mutation catches, or otherwise allow `getDb()` failures to reach the envelope handler.
