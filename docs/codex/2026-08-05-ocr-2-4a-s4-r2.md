The new reconciler operation update has a race that can terminalize a concurrently reclaimed, actively leased operation. This can discard active processing and leave its source document failed.

Review comment:

- [P1] Fence the reconciler's operation update — /workspaces/RecallMint/lib/exams/source-doc-status.ts:289-301
  If an expired operation is concurrently reclaimed after the source-document update's `NOT EXISTS` check but before this update, PostgreSQL's default READ COMMITTED isolation allows this statement to see and terminalize the newly leased operation. The source-document row lock does not lock the corresponding operation, and `claimOperationTx` only locks that operation row, so the stated absence of a competitor is not guaranteed. Recheck the live-lease condition or use lease-version fencing when terminalizing to avoid clobbering active work.
