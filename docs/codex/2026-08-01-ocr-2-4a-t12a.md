Full review comments:

- [P1] Reject operations whose source document was deleted — /workspaces/RecallMint/app/(app)/app/upload/_actions/publish-prepared.ts:165-173
  When the source document is deleted after staging, its `ON DELETE SET NULL` foreign key makes `sourceDocumentId` null, and this branch skips validation entirely. The transaction can then publish cards detached from the deleted source, potentially recreating user content during a deletion workflow; treat null as a missing source and abort instead of continuing.

- [P2] Persist terminal state for invalid prepared payloads — /workspaces/RecallMint/app/(app)/app/upload/_actions/publish-prepared.ts:397-405
  If stored payload data is corrupt or unexpectedly empty, these returns leave the operation in `prepared` with its lease and payload unchanged. Any takeover or retry worker will reclaim it and encounter the same permanent failure indefinitely, while replay cannot observe a persisted terminal result; transition the fenced operation to `terminal_failed` and record the reason before returning.
