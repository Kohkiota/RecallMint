### Task 1: sensors option 引数化(`lib/dnd/use-sortable-sensors.ts`)

- 目的: `useSortableSensors(options?: SortableSensorOptions)` に拡張する(spec §3)。
  - `export type SortableSensorOptions = { mouseActivationConstraint?: PointerActivationConstraint; keyboardCodes?: KeyboardCodes }`(両型とも `@dnd-kit/core` export 済 — dist 確認済。**2 key のみ・全 option 素通しの汎用化はしない**)。
  - Mouse へ `options?.mouseActivationConstraint`(あれば `{ activationConstraint: ... }`)、Keyboard へ `options?.keyboardCodes` を素通し。**Touch は不変**(`{delay:250, tolerance:5}`)。
  - 未指定 = 現行と完全同一構成。あわせて内部の inline literal(Touch options / Keyboard `{coordinateGetter}`)を module スコープ定数化(毎 render 新 object による `useSensor`/`useSensors` memo 無効化の解消 — fact-finding §1.1。挙動不変だが identity が安定化する)。呼出側が options に不安定参照を渡すと memo が死ぬ旨を doc comment に明記(spec §3 の安定参照規律)。
  - **custom 経路も memoize する**(test ⑧ の成立条件): `mouseActivationConstraint` / `keyboardCodes` を与えられた場合に `useSensor` へ渡す descriptor options object を `useMemo(..., [options?.mouseActivationConstraint])` / `useMemo(..., [options?.keyboardCodes])` で作る。呼出側が同一参照を渡し続ける限り hook 内でも新 object を生まないため、default 経路(module 定数)と custom 経路の**両方**で sensors 配列 identity が安定する。これを欠くと ⑧ は default 経路でしか green にならない。
- 制約: 既存 4 assert(Mouse constraint なし / Touch 値 / Keyboard coordinateGetter / 3 件順序)は**内容不変で green 維持**(tag 3 site の保証継続)。
- test(`use-sortable-sensors.test.ts` 拡張): ⑤ `mouseActivationConstraint: {distance: 4}` が Mouse descriptor options に透過 ⑥ `keyboardCodes` が Keyboard descriptor options に透過(coordinateGetter と共存)⑦ 未指定時は両 key とも undefined ⑧ **options 未指定 / 同一 options 参照の両方**で、rerender 後も戻り値 sensors 配列の identity が安定(定数化 + custom 経路 memoize の pin — 現行 inline literal では fail する = red 検証がこの変異で成立。custom 経路の memoize を外す変異でも fail することを個別に確認する)。
