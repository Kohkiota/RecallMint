# Grid-2 — 試験詳細テーブルのフィルタ + ソート + 一括操作 + 指標列 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (CLAUDE.md 既定実装方式) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grid-1 の試験詳細テーブルビューに、フィルタ (tag / 回答状態 / 数値比較) + ソート + 一括操作 (タグ付与 / 除去 / 削除) + 指標列 (read-only) を追加し、「絞り込み → 全選択 → 一括操作」を実現する。

**Architecture:** bulk 書込は既存 `runOptimisticMutation` (Y-1 prod 済) を流用し「1 rw tx 内で N mirror + N enqueue」を atomic に行う wiring 中心 (新 tx primitive を作らない)。フィルタ / ソートは useLiveQuery で読んだ flat 配列に対する TanStack `columnFilters` / `sorting` の client 側評価 (新規 fetch なし)。row data-shape を `full ClientCard` 化して指標 field を filterFn / cell から参照可能にする。

**Spec:** `docs/superpowers/specs/2026-06-17-grid-2-design.md` が正本。OQ は OT レビューで全件確定済 (plan で蒸し返さない、下記「OQ 確定結果」を制約として扱う)。

**Tech Stack:** Next.js 16 / TS strict / React 19.2.7 (Compiler OFF) / TanStack Table v8 (`@tanstack/react-table@8.21.3` 既導入) / Dexie 4.x / Tailwind v4 / vitest + fake-indexeddb / pnpm 10。新規依存は**追加しない** (toast lib は導入しない = §OQ-3)。

## Open Questions (実装着手前に方針確定、各案 + CC 推奨)

### OQ-1: `CardTagAddPopover` 流用 adapter の正確な境界

- 案 A (CC 推奨): **adapter component が popover を wrap し、popover の「option 選択」コールバックを「即付与」ではなく「filter / bulk-op 対象の (categoryId, optionId) を返す」へ差し替える**。popover 内部 (5 stage machine / selectedCategoryId) は無改造、`initialStage='option'` + `initialCategoryId` の既存 props (Grid-1 T3) のみ利用。共有するのは「カテゴリ→option を選ぶ UI」、分岐するのは「選択確定時の副作用」。
- 案 B: popover に `mode?: 'assign' | 'select'` props を追加し内部分岐。本体改造になり regression gate (popover 不侵食) と背反。
- 案 C: フィルタ / bulk 用に専用 option 選択 UI を新設 (A-2 フォールバック)。重複だが popover と疎結合。

CC 推奨: **案 A**。popover 本体を一切触らず副作用だけ外側で差し替えるため Grid-1 regression gate を守れる。adapter が「選択確定の検知」で popover 内部 state に手を入れる必要が出た時点 (= 案 A が破綻) で案 C にフォールバックし停止 → OT 相談。T3 着手前に確定したい。

### OQ-2: bulk helper の正確な signature

- 案 A (CC 推奨): tag = `useBulkCardTags({ userId, getCardTags }): (cardIds, categoryId, optionId, op:'add'|'remove') => Promise<BulkResult>` / delete = `useBulkCardDelete({ userId }): (cardIds) => Promise<BulkResult>`。`getCardTags(cardId)` は親の live data を closure capture した getter (hook 内 useLiveQuery 禁止、単票 T2 と同じ getter pattern)。`BulkResult = { ok; succeeded: string[]; failed: string[] }` で失敗 UI (T6) に渡す。
- 案 B: live data を hook 引数で直接渡す (getter なし)。live data 更新で hook 戻り identity 変動 → 再描画増。
- 案 C: React 外の module 関数 `bulkCardTags(deps, ...)`。表面積最小だが caller が deps を毎回手渡し。

CC 推奨: **案 A**。getter pattern で identity 安定 (T2 と一貫)、`BulkResult` で失敗件数を T6 失敗 UI に素直に渡せる。正確な型は T4 着手時に確定。

### OQ-3: bulk 失敗 UI (toast 基盤の有無)
