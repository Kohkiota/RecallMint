**Goal:** Tag-4a smoke (`docs/superpowers/sessions/2026-06-07-tag-4a-stg-smoke.md`) で発見した UX 課題 2 件を fix する:
1. **Optimistic 更新**: 全 mutation (category/option × create/rename/color/move/delete) で IDB 即時 put/delete + enqueue 並列、 UI 即時反映 (現状は pull 経由でしか反映されない)
2. **Row click 誤起動**: category-row / option-row で name が row 大部分を覆って rename を誤起動 → 名前は static span、 横に lucide `Pencil` icon button を明示 edit trigger として配置、 row 全体 click は active 切替 (category-row のみ) に分離

**Architecture:** 既存 `app/(app)/app/exams/[id]/_components/inline-text-field.tsx:159` の `getClientDb().cards.update(cardId, ...)` + `enqueueEntityMutation` 並列パターンを Tag-4a の全 form/row に踏襲。 削除時の cascade は client 自前 purge (案 a の cascade purge と一貫、 idempotent)。 lucide `Pencil` は既存 `components.json:iconLibrary` 設定済、 `lucide-react` deps 不要追加。

**Tech Stack:** TypeScript strict / Dexie 5 (`getClientDb` の direct put/update/delete) / `lucide-react` (`Pencil` icon、 既存 deps) / Vitest + React Testing Library。

**前提:**
- Tag-4a (commit `a26ecd5`) で UI が着地、 全 form/row は `enqueueEntityMutation` のみで IDB put 未実装

### Task 1: 全 form/row に optimistic 更新を追加

**Files:**

- Modify: `app/(app)/app/tags/_components/category-create-form.tsx` (+10 行: `db.tag_categories.put(optimisticRow)` を enqueue 前に追加)
- Modify: `app/(app)/app/tags/_components/category-row.tsx` (+25 行: rename 時 `db.tag_categories.update(catId, {name, updated_at})`、 delete 時 `配下 option/card_tags purge → db.tag_categories.delete(catId)`)
- Modify: `app/(app)/app/tags/_components/option-create-form.tsx` (+10 行: `db.tag_options.put(optimisticRow)`)
- Modify: `app/(app)/app/tags/_components/option-row.tsx` (+25 行: rename / color / move 時 `db.tag_options.update(optId, ...)`、 delete 時 `配下 card_tags purge → db.tag_options.delete(optId)`)
- Modify: `app/(app)/app/tags/_components/category-create-form.test.tsx` / `category-row.test.tsx` / `option-create-form.test.tsx` / `option-row.test.tsx` (+150 行 合計: mock の put/update/delete 呼出確認)

**目的:** 全 mutation で IDB 即時更新 → useLiveQuery が即時再描画 → ユーザー操作直後に UI 反映。 既存 `inline-text-field.tsx:159` の `getClientDb().cards.update(...)` + `enqueueEntityMutation` 並列 pattern と同形。

**制約:**

- **発行順序**: IDB put/delete → `enqueueEntityMutation` → `runGuardedEntityMutationFlush` の 3 段。 IDB を **先に** 発行する (UI 即反映の保証)。 enqueue は `void` 発火、 await 不要 (form reset は同期で OK)
- **削除時の cascade purge (client 自前)**:
  - category delete: 配下 option を取得 → 配下 option_id を持つ card_tags を `db.card_tags.where('option_id').anyOf(optionIds).delete()` → 配下 option を `db.tag_options.where('category_id').equals(catId).delete()` → `db.tag_categories.delete(catId)` の 4 段
  - option delete: option_id を持つ card_tags を `db.card_tags.where('option_id').equals(optId).delete()` → `db.tag_options.delete(optId)` の 2 段
  - server cascade は別経路で同等処理が走るが二重削除 idempotent、 pull で reconcile
- **optimisticRow の field**: `user_id` は空文字 `''` (現 user_id を client から知る経路なし、 server pull で正しい値に上書きされる)、 `created_at` / `updated_at` は `new Date().toISOString()`、 `color: null` / `sort_key: null` (作成時 default)
- **rename / color / move (update)**: 既存 row の field を `update()` で部分更新、 `updated_at` も同時 bump (`new Date().toISOString()`)
- **既存 `enqueueEntityMutation` / `runGuardedEntityMutationFlush` の signature は不変** (server-side mutation の発行はそのまま)
- **server failed の rollback は実装しない**: 既存 entity-mutation-flush の retry + pull で reconcile を信用。 client 側の即時 rollback は overkill (Tag-2 smoke 経験から、 既存経路は network 起因の失敗以外 fail しないことを確認)

**完了条件:**

- `pnpm test` 全件緑 (新規 test mock 含む)
- `pnpm build` 緑
- 各 form/row test で IDB put/update/delete 呼出が enqueue より先に発行されることを mock spy 順序で gate

### Task 2: row click 分離 + pen icon button (category-row + option-row)

**Files:**

- Modify: `app/(app)/app/tags/_components/category-row.tsx` (+30 行: name button → static span + `<Pencil />` icon button + row 全体 onClick で active 切替 + a11y `role="button"` + tabIndex + Enter キー対応)
- Modify: `app/(app)/app/tags/_components/option-row.tsx` (+25 行: name button → static span + `<Pencil />` icon button、 ただし active 切替 onClick なし)
- Modify: `app/(app)/app/tags/_components/category-row.test.tsx` (+50 行: row click → onSelect / pen icon click → rename mode + stopPropagation 確認 / keyboard Enter で active 切替 / a11y)
- Modify: `app/(app)/app/tags/_components/option-row.test.tsx` (+30 行: pen icon click → rename mode、 既存 test の name button click 経路を pen icon click に書換え)

**目的:** 編集 trigger を「明示的な pen icon button」 に統一して、 ユーザーの操作モデル (row click = 選択 / pen click = 編集) を明確化。 Tag-4b の card 列タグ UI の型紙として、 「編集トリガー = 明示的 icon」 を category-row / option-row で揃える。

**制約:**

- **lucide `Pencil` icon** (`import { Pencil } from 'lucide-react'`)、 size `w-4 h-4`、 `aria-label="編集"`、 button は `text-slate-500 hover:text-slate-900` 等で控えめに
- **name は `<span>` static**: editing=false 時に表示、 button ではない (row click で active 切替に bubble)
- **rename mode (editing=true)**: 既存 inline-text-field input UI を踏襲、 input が表示されている間は pen icon 非表示
- **stopPropagation**: pen icon click と 削除 button click は `e.stopPropagation()` で row click と分離
- **category-row only**: row 全体 `<div role="button" tabIndex={0} onClick={() => onSelect(category.id)} onKeyDown={(e) => e.key === 'Enter' && onSelect(category.id)}>` で active 切替 + a11y。 既存 `active` 状態の class `bg-slate-100` 等は維持
- **option-row**: active 切替なし (right panel 全 option active 扱い)。 row 全体は static、 name の横に pen icon、 click 操作は color pill / 移動 / 削除 button それぞれ独立

**完了条件:**

- `pnpm test` 全件緑
- `pnpm build` 緑
- a11y test: row に `role="button"`、 keyboard Enter で active 切替、 pen icon button が独立して操作可能
- 既存 test 中、 「name button click で rename」 系の test を「pen icon click で rename」 に書換え (option-row 既存 test 含む)
