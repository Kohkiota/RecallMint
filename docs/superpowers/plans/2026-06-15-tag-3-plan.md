# Tag-3 — OCR auto-tag 分解書込 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (CLAUDE.md 既定実装方式) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** OCR が discover mode で抽出する `custom_props` を `tag_categories` / `tag_options` / `card_tags` に find-or-create + bulk INSERT で分解保存する path を新設し、 Tag-1 で DROP した `cards.custom_props` の代替を完成させる。

**Architecture:** 新規 helper `lib/tags/apply-ocr-tags.ts` を server-only で起こし、 `process.ts` の cards INSERT tx (L533-549) に atomic 同梱する。 find-or-create は 2 段 SELECT + `ON CONFLICT DO NOTHING` + 再 SELECT (UNIQUE 競合は正常系、 rollback トリガーにしない)。 per-upload Map で同名集約。 sort_key は in-memory 累積。

**Spec:** `docs/superpowers/specs/2026-06-15-tag-3-design.md` (`8126029` 確定版) が正本。

**Tech Stack:** Next.js 16 / TS strict / Drizzle (postgres-js) / Dexie / vitest / pnpm 10。

### Task T1: `apply-ocr-tags.ts` helper 新設 (find-or-create + per-upload 集約 + bulk INSERT)

**Files:**
- Create: `lib/tags/apply-ocr-tags.ts`
- Create: `lib/tags/apply-ocr-tags.test.ts`

- [ ] **目的**: OCR の `pipelineResult.cards[].custom_props` を `tag_categories` / `tag_options` / `card_tags` に分解書込する server-only helper を起こす (spec §6.1)。 入力 = `(tx, userId, cardsWithCustomProps[])`、 戻り値 = `void` (失敗は throw で tx 巻き込み、 spec §4)。
- [ ] **制約**:
  - server-only (`import 'server-only'`)、 全 query に `userId` 必須 (CLAUDE.md Clerk §3)。
  - 正規化 = `.trim()` のみ (`tagNameSchema` と同方針)。 空文字 key / value は skip (`.trim() === ''` で除外)。
  - find-or-create 2 段 + ON CONFLICT DO NOTHING + 再 SELECT (spec §3.1)。 既存 row hit は `failed` ではなく id 取得して再利用。
  - per-upload Map (`Map<trimmedName, id>` for category / `Map<categoryId + sep + trimmedName, id>` for option) で同名集約 (spec §3.2)。 sep は ASCII `\x1f` (Unit Separator) で固定、 NUL 不使用 (前 commit 1492e24 の NUL byte 教訓)。
  - sort_key = `nextSortKey(existing)` 起点に in-memory 累積採番 (spec §3.3)、 manual race drift は受容 (spec §8.3)。
  - 新規 default: tag_category `select_type='multi'` / `color=null` / `sort_key=末尾`、 tag_option `color=null` / `sort_key=同 category 内末尾` (spec §3.4)。
  - `apply-tag-mutation.ts` (entity_mutations 経路) は再利用しない (id-specified / 衝突=failed セマンティクスが異なる、 spec §6.1)。
- [ ] **完了条件 (test 戦略 spec §7 二分化)**:
  - **(a) 構造 + 値 correctness** (7 case):
    1. find: 既存 category / option が trim 一致で再利用される (新規 INSERT 0 回)
    2. create: 新規 category default = `select_type='multi'`, `color=null`, `sort_key='0'` (空 DB) or `nextSortKey(existing)+α`
    3. create: 新規 option default = `color=null`, `sort_key` 末尾累積
    4. 集約: 同 upload 内同名 (category / option) は同 id 流用 (1 INSERT のみ)
    5. trim: `'年度 '` と `'年度'` を同 row として merge する
    6. card_tags: `(card_id, option_id)` PK で同 pair 重複なし
    7. rollback: 予期せぬ DB error (mock injection で `tx.insert(...).onConflictDoNothing` を throw) → throw 伝播 (caller tx 巻き込み確認は T2 で)
  - **(b-i) tenant isolation 構造** (1 case): find SELECT / INSERT 句に `userId` が必ず含まれる (T-B4 流の `as unknown as unknown[][]` spy で構造保証)
  - test mock = drizzle tx mock (entity-mutation-registry.test.ts 等の先例)。 実 DB 接続なし。
  - `pnpm typecheck` + `pnpm test lib/tags/apply-ocr-tags.test.ts` exit 0。
  - canonical review (`superpowers:requesting-code-review`)、 Critical 0、 [reviewed] 付与。 commit message: `feat(tags): T1 apply-ocr-tags helper 新設 (find-or-create + per-upload 集約 + bulk INSERT) [reviewed]`。
