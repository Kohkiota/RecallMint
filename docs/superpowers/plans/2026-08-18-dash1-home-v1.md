### Task 4: origin パイプライン(wire → ingest 正規化)

- 目的: origin を client 記録から DB 保存まで通し、未知値を null 正規化する(spec §11)。
- 制約: `answer-event-schema.ts`(`origin: z.string().max(64).optional()`)/ `lib/sync/review-events.ts` 3 箇所透過 / **UI props chain**: `session-runner.tsx`(recordAnswerEvent へ)← `SessionRunnerProps` ← `session-launcher.tsx` ← `study-session-host.tsx`(この時点は `'smart'` 固定)/ `custom-session-flow.tsx`(`'custom'`)— sessionId と同経路(spec §11.4。smart の値の動的化は Task 6、quick は Task 7)/ `ingest-review-events.ts`(`ORIGIN_VALUES` 判定 → 未知値 null + `logger.warn` event **`review_events.bulk.origin_normalized`**)/ `session-repository.ts:AnswerEventInsertRow` +1。**`CollisionCandidate` は不触**(比較対象外 — spec §11.4)。

- 完了条件: iso 4 本(未知値 null 正規化で batch 200 / 既知値保存 / 再送で既存行の origin 不変 / origin 違い再送が collision にならない)+ unit(wire 透過 + **log event 名と 1 行/batch の pin**)+ **red 検証** / [reviewed]。
