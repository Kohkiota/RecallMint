# 調査レポート: ツール呼び出しが本文にテキスト漏れして実行されない不具合

- 作成: 2026-07-03 / 種別: postmortem(再発性の生成不具合)
- 文脈: Notion 式テーブル S1 実装 session 中に複数回発生し進行が止まった。

## 1. 症状

CC(assistant)がツール(Bash / Write 等)を呼ぼうとした際、呼び出しが**ツール呼び出しとしてパースされず、本文テキストとしてそのままユーザーに表示**される。ツールは**実行されない**ため作業が進まず、ユーザーが「また止まった」と気づいて指摘 → CC が再発行、を繰り返した。

漏れた出力の典型形（先頭に stray 語 + 名前空間なしのタグ）:

```
court
  <invoke name="Bash">
  <parameter name="command">git add ...</parameter>
  </invoke>
```

## 2. 根本原因

このハーネスの正しいツール呼び出し記法は **`antml:` 名前空間付き**の関数呼び出しブロック:
`function_calls` ラッパ内に `invoke name="X"` … `parameter name="Y"` … を、いずれも `antml:` 名前空間付きタグで出す。

defect は次の 2 点が同時に起きること:
1. **名前空間 `antml:` の欠落** — invoke / parameter / 閉じタグを素で出力。名前空間が無いためハーネスが関数呼び出しと認識できず、ブロック全体が plain text 化する。
2. **先頭に stray トークン `court` 混入** — 本来の開始トークン（function_calls の opener）を生成し損ねた際の別トークンへの化け。

発生条件: **長い prose ブロック（commit 直前宣言・状況報告など）の直後**にツール呼び出しを出すときに集中。構造化 opener の生成が prose 慣性で滑る。

## 3. 影響

- 機能影響なし・**副作用ゼロ**。malformed 呼び出しは実行されないため、git / ファイル状態は一切変化しない（作業ロスなし）。
- 進行影響大。CC は「呼んだつもり」で停止 → 人手の再指示が要る → 往復で時間浪費。自走が途切れる。

## 4. 復旧手順（確立済）

1. `git status` で working tree 確認（malformed のみなら未変更のはず）。
2. 直前に意図した呼び出しを、**正しい `antml:` 名前空間記法**で再発行。
3. 通常フロー継続。状態巻き戻し不要。

## 5. 再発防止

| 対策 | 種別 | 強度 | 状態 |
|---|---|---|---|
| memory 記録（`feedback-tool-call-syntax-error`）| 受動リマインダ | 低〜中 | 済 |
| 本調査レポート（lessons）| 参照資料 | 低 | 本 file |
| **Stop hook 検出**（下記）| 半機械的 | 中 | 実装予定 |
| 自己規律（prose 直後でも記法厳守・先頭に語を付けない）| 行動 | — | 恒常 |

### なぜ「完全な機械的ガード」が難しいか

この不具合は出力が**そもそもツールイベントとして発火しない**（テキスト化する）。PreToolUse 等の hook は「ツールイベント発火時」しか動けないため、**発火しない malformed 出力は tool hook で捕捉不能**。唯一の機械的シグナルは「最終メッセージ本文に生の invoke リテラルが残る」こと → **Stop hook** で本文を走査するのが現実解。

### Stop hook 検出設計（誤検知回避）

- トリガ: 最終 assistant メッセージ本文の**行頭**（先行空白のみ許容）に名前空間なしの invoke/parameter 開始タグ、または `court` 単独行が出現。
- 行頭アンカーにより、本文中に backtick 等で囲んだ inline 言及は**誤検知しない**（漏れた実呼び出しは必ず行頭から始まる）。
- 検出時: Stop を block し「ツール呼び出しが未実行のまま漏れている。`antml:` 名前空間付きで再発行せよ」と reason を返す → CC が同ターンで再発行できる。
- 置き場: 個人の `.claude/settings.local.json`（gitignore）。CC 固有の記法クセのガードゆえチーム共有 `settings.json` に載せない。

## 5.1 これは Claude Code の既知バグ(harness 側)

CC 固有のクセでなく harness の既知不具合。関連 issue: anthropics/claude-code #64108 / #60584 / #62344 / #66400 / #68354 等(いずれも未修正)。集約した特性:

- **副作用ゼロ**(未実行)。retry は大抵成功する。
- **self-poisoning**(#62344): 漏れた markup が context に残ると再発率が上がる。**繰り返す場合の確実な回復は新セッションのみ**。
- **prose 直後**の呼び出しで発生しやすく、**「prose なしで応答の先頭要素として再発行」が有効 workaround**(#60584)。

## 5.2 本 hook の限界

- 自動復旧は **1 回まで**(`stop_hook_active=true` で 2 回目は抑止 = 汚染セッションで retry が再発源になるのを防ぐ)。
- 根本修正は **harness 側でしか不可能**。本 hook は「漏れたまま黙って止まる」のを防ぐ検出・再促しに留まる。
- 名前空間欠落で**ツールイベントが発火しない**ため PreToolUse では捕捉不能。Stop hook で本文走査するのが唯一の実装可能な検出面。
- 依存: `python3`(この環境に `jq` は無い。既存 `discord-notify.py` と同じ python3 で実装)。

## 6. 教訓

- ツール呼び出しは prose の慣性から独立して、**opener トークンと `antml:` 名前空間を厳密に**出す。
- 「実行したつもり」で報告しない。ツール結果を確認してから次へ（evidence before assertions）。今回は結果が返らない=未実行のシグナルだった。
