## §2 実コード (T-B7 対象)

### 2a. 現行実装 (`lib/cards/get-dexie-session-cards.ts:23-38`、 改訂前)

```ts
export async function getDueCardsFromDexie(
  userId: string,
  limit: number,
  now: Date = new Date(),
): Promise<Card[]> {
  const nowIso = now.toISOString()
  const userCards = await getClientDb()
    .cards.where('user_id')
    .equals(userId)
    .toArray()
  const due = userCards
    .filter((c: ClientCard) => c.due <= nowIso)
    .sort((a, b) => (a.due < b.due ? -1 : a.due > b.due ? 1 : 0))
    .slice(0, limit)
  return due.map(toCard)
}
```

- query method: `where('user_id').equals(userId).toArray()` 経由 + JS filter + sort + slice
- 戻り値用途: `Card[]` (toCard mapper 経由)、 呼出元 (`study-session-host.tsx:62`) で session 開始用 card 集合として消費
- 旧経路は「user_id index 経由で row body fetch (= user 全 cards、 power user で 2k+) → JS filter で due <= now → JS sort → slice(0, limit)」 で、 body fetch + JS sort/filter の両方が cost。

### 2b. 不変条件 (実装後も完全一致させる対象)

- **集合**: `user_id` 等価 ∧ `due <= nowIso` (inclusive)
- **並び**: `due` ASC (旧 JS sort は同値時 engine 依存だが modern V8 は stable、 新 index 順は `(user_id, due, primary key)` lex 順で安定)
- **件数**: `slice(0, limit)` で limit 件 (default 20 = `user_settings.session_limit` fallback)
- **tenant 絞り**: user_id 必須 (引数で受け取り、 Dexie query で第 1 要素 equals fix)
- **戻り型**: `Card[]` (server camelCase + Date)、 `toCard` mapper 経由
- **呼出元**: `study-session-host.tsx:62` で `getDueCardsFromDexie(userId, sessionLimit)` (now 引数なし → `new Date()`)
- **session_limit 出所**: `user_settings.session_limit`、 未設定 fallback **20** (`app/(app)/app/study/smart/page.tsx:27` + `lib/db/schema.ts:488`)

## §4 Dexie 公式 docs 裏取り (Context7 `/websites/dexie`)

### 4a. compound index range query は index 順で sorted (公式 docs より)

> Illustrates a range query on a compound index '[firstName+lastName]' to find all people whose firstName is 'Anna' and lastName starts with 'L'. **The results are sorted by lastName.**
> Source: https://dexie.org/docs/Compound-Index

```javascript
db.people
  .where('[firstName+lastName]')
  .between(
    ["Anna", "L"],
    ["Anna", "L￿"]
  ).toArray();
```

- 第 1 要素固定 + 第 2 要素 range の between では結果が第 2 要素 ASC で sorted 返却される
- T-B7 の場合: `where('[user_id+due]').between([uid,'0'],[uid,nowIso], true, true)` で due ASC が構造的に成立、 `.sortBy()` 不要

### 4b. `.limit(N)` は cursor を N 件で止める (公式 docs より)

> Limits the number of records returned by a collection query.
> Source: https://dexie.org/docs/Dexie/Dexie.waitFor%28%29

- IndexedDB cursor は lazy enumeration、 `.limit(N)` で N 件 fetch 後 cursor.continue() を呼ばないため body fetch 最大 N 件
- T-B7 では `.limit(sessionLimit)` (default 20) で旧の user 全 cards body fetch (power user で 2k+) から strictly 軽い構造

### 4c. `.sortBy()` を呼ばない判断根拠

- index 順 fetch (上記 4a) で due ASC が成立するため `.sortBy()` は不要
- `.sortBy()` を呼ぶと Dexie 内部で全件 materialize → JS sort になり、 limit(N) 適用前の cursor enumerate が崩れる → index 利点を消す罠
- 旧 JS chain の `.sort()` 撤去 = index 順 fetch に委譲する形
