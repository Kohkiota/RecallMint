### 5.3 scenario 到達可能性

- **A (other=0)**: 単一 exam user (= 現 stg test user 状態) で常時該当

### 5c 判定: 短期 1 年 = A-B、 長期 1-5 年 = B-D 到達可能 (実効場面ありうる)

- **A (実機 0 ms 体感差なし) は当該 stg test user / 短期使用 user で常時該当**

- **C-D (heavy / extreme、 37-152 ms 差、 体感 jank 閾値超え) は 1-5 年使用の power user / long-term user で到達**
- 「実効場面なし」 ではない (B-D は将来到達する scale)、 ただし「現状実機 = 0 件 = A scale」 で typical 短期 user で 0 体感差は事実

### 8.1 完了条件 (b) test 形式の決定経緯

完了条件改訂 初版 commit (`e8c678d`) で (b) を **wall-clock < 5 ms の unit test assert** としたが、 実装 + test 投入後の per-task gate (lint exit 0 / typecheck exit 0) を経て test 実行で:
- `app/(app)/app/exams/[id]/_components/inline-card-list-live.test.tsx` の (b) test が **26.56 ms vs ceiling 5 ms = fail**

原因 = fake-indexeddb は **memory-based JS 実装で anyOf の cursor walk が実 IDB の B-tree index seek より遅い**。 plan policy 「**jsdom/mock を perf 根拠にしない、 fake-indexeddb は集計 correctness 確認に限定**」 と衝突。

OT 判断 (2026-06-14 chat) で **案 1 = 構造 assert 化** で確定:
- **(b-i) 構造 unit**: anyOf 経路が他 exam の card_id を含まないことを assert (= 「無駄読みゼロ」 を perf でなく構造で担保)
- **(b-ii) wall-clock**: stg 実測 (本 file §3: anyOf 4.04 ms mean / stdev 0.75 at 200 tags / 0 other = 知覚不能域) を正本、 unit test には wall-clock ceiling を新規導入しない

理由 (記録):
- **plan policy 準拠** (`jsdom/mock を perf 根拠にしない`)。 fake-indexeddb 実装特性と実 IDB の差を unit test の正/否で担保しない (環境差の偶発に晒される)
- **wall-clock の正本は stg**。 本 file §3 で 10 run / stats 付きで取得済、 既に anyOf 4.04 ms mean は知覚不能域の証明として完了条件 (b-ii) を満たしている
- **「構造で担保」 への切替**は「test が落ちたから ceiling を緩めた」 ではなく、 **plan policy と OT 指示の衝突を policy 優先で解消**した結果 (OT 承認済 2026-06-14)
