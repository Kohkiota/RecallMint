- **書込**: 既存 `useMoveCards` / `card_move` op を**無変更で素通し**。DB migration・wire・server・sync は一切触っていない。
- **DnD 構造**: `DndContext` / `DragOverlay` は**常時 mount**(条件 mount は provider の型変化 tear-down で全行 remount = Fix-3 T1.1 と同 class)。`SortableContext.items` は仮想表示行ではなく基準順**全** card id。`verticalListSortingStrategy` + `closestCenter` + 自前 `restrictToVerticalAxis`(`@dnd-kit/modifiers` 不採用)。
- **handle**: select セル内の専用 button。`touch-none` と dnd-kit の `listeners`/`attributes` は **handle のみ**(event 分離契約)。`setNodeRef` と virtualizer の `measureElement` は **identity 固定 merge ref** で結合。`aria-describedby` は dnd-kit 側の値と**合成**。
- **gating**: 既存 `positionLocked` を流用し、handle gate + `useSortable` disabled + `onDragEnd` 再検査の 3 層。
- **toast/undo**: 成功「並び順を変更しました [元に戻す]」は既存 toast slot / `ActionToast` / `onUndoMove` を共用。失敗は undo なしの「並べ替えに失敗しました」。

## 6. 教訓

1. **plan の内部非整合は 2 系統の reviewer が独立に同じ形で検出する。** Task 3 の「幅は広げる」と「視覚変化なし」は同じ段落に同居していたが、pre-flight scan では「task 間の interface 突き合わせ」に気を取られて見落とした。**同一 task 内の自己整合(この task が主張する不変条件と、この task が加える変更が両立するか)を明示的に 1 行ずつ照合する**のが scan の欠けていた半分。
2. **「壊れた test を直した」は保証が消えた瞬間になりうる。** Task 4 は `DndContext` 常設で dnd-kit の live region が `role="status"` を常設し、既存 12 test の query が曖昧化した。implementer は `aria-live` 判別 helper で修正したが、**reviewer が「肯定・否定の両極性で使われているか」を確認して初めて vacuous pass でないことが示された**。query 方式の変更は assertion を消さないので diff からは無害に見える。
3. **IDE 診断は stale になる。** 未使用 helper(6133)を review 観点として reviewer に渡したが、canonical が全使用箇所を列挙し `tsc --noEmit` でも無指摘であることを確認して false positive と判明。**診断を根拠に指摘を組み立てる前に、その診断が現物と一致するか自分で確認する**。
4. **型シグネチャは実体を語らない。** `DndContextProps['onDragEnd']` は `=> void` 宣言だが実体は async handler で、`await` は `finally` まで待つ。TS の「`await` has no effect」は型レベルの artifact であり、race の証拠ではなかった。
5. **常時 mount の代償は DOM に現れる。** provider を条件 mount しない判断(remount tear-down の回避)は正しいが、その結果 dnd-kit の live region と SR instructions が全ユーザーに常設される。設計判断は「消える副作用」ではなく「別の場所に現れる副作用」を持つ。
