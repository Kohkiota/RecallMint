### 5.6 smoke で判明した事項(FAIL ではないが記録)

- **A. keyboard drop 後に focus が `document.body` へ落ちる**(#11)。dnd-kit の `restoreFocus` は activator ノードへ戻す設計だが、drop で行が再配置され元ノードが外れるため復帰先を失う。Grid-3 で行メニューが踏んだ「mount 時に記録した要素が同 commit で unmount される」と同 class。keyboard 利用者は drop のたびに tab し直しになる。**規定の判定基準(動作確認レベル)は満たすため PASS 扱い**、対処は OT 判断。
- **B. 背の高い行では小さな drag が「移動方向と逆の隣接行」に着地しうる**。DragOverlay を使うと collision rect が **cursor 位置の小さな overlay** になる。handle は行の上端付近にあるため、603px の行を 26px 下げただけでも overlay 中心は自行の中心(+300px)より**上の行の中心**に近く、`closestCenter` が上の行を選ぶ(実測: 下方向 26px の drag で上の行の位置へ着地)。**データは常に drag 中の transform preview と一致**しており不整合ではない。ヒット判定が cursor でなく「overlay 中心 vs 行中心」である点が直感とズレる。
- **C. #8 touch は emulation では答えが出ない**。仮に `hasTouch` context を作れても、Playwright の合成 touch は long-press 250ms と native scroll gesture の**調停**(compositor 側)を再現しない — #8 の唯一の争点がそこなので、低忠実度の代替は判断材料にならない。

### 5.7 method 上の注意(次に同じ smoke を回す人へ)

- **測定前に内部 scroll container を必ず 0 にリセットする**。本 smoke では 2 回、scroll 残留により handle の bounding box が負座標になり「drag が発火しない」偽 FAIL を観測した(いずれも harness 起因と切り分け済み)。
- `browser_drag`(Playwright の dragTo)は **DragOverlay が pointer events を遮って mouseup の actionability check に失敗する**。raw `page.mouse.move/down/up` を段階的に使うこと。

## 6. 教訓

1. **plan の内部非整合は 2 系統の reviewer が独立に同じ形で検出する。** Task 3 の「幅は広げる」と「視覚変化なし」は同じ段落に同居していたが、pre-flight scan では「task 間の interface 突き合わせ」に気を取られて見落とした。**同一 task 内の自己整合(この task が主張する不変条件と、この task が加える変更が両立するか)を明示的に 1 行ずつ照合する**のが scan の欠けていた半分。
2. **「壊れた test を直した」は保証が消えた瞬間になりうる。** Task 4 は `DndContext` 常設で dnd-kit の live region が `role="status"` を常設し、既存 12 test の query が曖昧化した。implementer は `aria-live` 判別 helper で修正したが、**reviewer が「肯定・否定の両極性で使われているか」を確認して初めて vacuous pass でないことが示された**。query 方式の変更は assertion を消さないので diff からは無害に見える。
3. **IDE 診断は stale になる。** 未使用 helper(6133)を review 観点として reviewer に渡したが、canonical が全使用箇所を列挙し `tsc --noEmit` でも無指摘であることを確認して false positive と判明。**診断を根拠に指摘を組み立てる前に、その診断が現物と一致するか自分で確認する**。
4. **型シグネチャは実体を語らない。** `DndContextProps['onDragEnd']` は `=> void` 宣言だが実体は async handler で、`await` は `finally` まで待つ。TS の「`await` has no effect」は型レベルの artifact であり、race の証拠ではなかった。
5. **「非 null」を確かめる assertion は、常に値が入る属性では何も確かめていない。** `aria-describedby` は dnd-kit が必ず自前 id を載せるため、非 null チェックは table 側の sr-only 要素を削除しても green のままだった。**その属性を誰が書いているかを数えてから assertion の形を決める**。修正版は id list を分解して参照先の text まで見る形にし、sr-only 削除で当該行のみが fail することを red 検証した。
6. **常時 mount の代償は DOM に現れる。** provider を条件 mount しない判断(remount tear-down の回避)は正しいが、その結果 dnd-kit の live region と SR instructions が全ユーザーに常設される。設計判断は「消える副作用」ではなく「別の場所に現れる副作用」を持つ。
