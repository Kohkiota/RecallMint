## P2 最重要制約(これを割ったら停止)

- **P0 golden が review-events / entity-mutations / upload / webhook の契約を凍結済み**: payload shape / error code / HTTP status / user-facing 日本語文言 / cache header / revalidatePath 対象 / op 名 / ops イベント名(D-2)。
- P2 は **golden を割らずに route から中身を抽出**する。**golden が赤 = 挙動が変わった = 即停止**。
- 凍結契約 inventory = P0 baseline §B(i)。特に upload の 11 error code + `ProcessUploadResult` union 形は P2 の process.ts 分解が最初から参照すべき境界。

## P2 の地雷(audit §6.3 — 分割設計で最も事故る点)

- **review-events の単一 tx 境界 + count mismatch 防御**: session upsert / answer_events / reviews / study_days を 1 tx で書く不変条件。抽出で tx をまたぐと部分反映が起きる。
- **process.ts の advisory lock 保持前提の tx 境界**: 分割を誤ると採番 race(in-flight guard の意味が消える)。lock 取得〜解放の範囲を跨ぐ抽出をしない。
- **webhook の「error でも 200」意味論**: handler error も 200 を返す(再送ループ防止)。invalid signature のみ 400。P0 golden が状態遷移込みで固定済み — 抽出で status/文言を変えない。

1. **現 HEAD で P2 対象を fact-finding(再スキャン)** — audit の file:line が生きているか、行数・構造を実測。P1 の carve-out で lib/ 側の pure 資産は既に整理済み(streak-core / derive-exam-statuses / subscription-changes / card-filter-predicates / custom-session-criteria)なので P2 の抽出先と衝突しないか確認。
2. **spec 起草**(brainstorming step6)→ self-review → **User Review Gate で OT 確認**。
3. plan 起草(writing-plans)→ **Codex plan cross-check(plan 確定前)** → OT 承認で確定。
4. subagent-driven で実装。canonical review 全 code task / Codex + build は risk task(tx 境界・決済・認証に触れる task)。full test は最終 gate 集約。
