## 仕様まとめ

### 基本記法（Anki 公式）

| 記法 | 意味 | 表示 |
|---|---|---|
| `{{c1::答え}}` | 穴埋め化 | `[...]` |
| `{{c1::答え::ヒント}}` | ヒント付き穴埋め | `[ヒント]` |
| `m{{c1::any}}` | 単語の一部だけ穴埋め | `m[...]` |

### カード番号の意味

| パターン | 結果 |
|---|---|
| 同じ番号（全部 c1） | **1 カードに統合**、解答表示で全部一括開示 |
| 異なる番号（c1, c2, c3） | **別カード分割**、c1 のカード / c2 のカード / c3 のカード |

### 制約

- **入れ子不可**: cloze の中に cloze を書けない
- **数字制限なし**: c1〜cN まで可（N 上限は実用上問題にならない）

### 画像穴埋め（Image Occlusion）

- 別ノートタイプ「画像穴埋め問題」を使用
- 画像をアップロード → マスキング箇所をドラッグで選択
- 複数マスキング = 別カード生成（デフォルト）
- 「グループ化」操作で 1 カードに統合可能
- アドオン `Image Enhanced Occlusion` で機能拡張可（mcq-platform には不要）

### AI を使った効率化（Tab Works 2025 推奨）

ChatGPT 等に以下のプロンプトを投げると、Anki にインポート可能な txt が生成される:

```
12種の脳神経を3つごとに分けポイント説明を行った後、Anki穴埋め用にクロズを施し、UTF-8のtxt形式で出力してください。
```

応用パターン:

- 「(スキャンした) レジュメから要点を抜き出し、Anki 穴埋め用にクロズを施し、UTF-8 の txt 形式で出力してください」
- 「この英単語リストを、Anki 穴埋め用にクロズを施し…」
- 「教材から頻出部位を抜き出し、Anki 穴埋め用にクロズを施し…」

Anki インポート時は「フィールドの区切り = タブ」「ノートタイプ = 穴埋め問題」を指定。

時短効果: 手動 1 題 3-5 分 → AI で 100 題が数分。**穴埋め部分を完全自動化できる**のが本質。

## mcq-platform への示唆

### MCQ と cloze の関係

| 形式 | 入力 | 答え方 | 用途 |
|---|---|---|---|
| MCQ | 選択肢から選ぶ | クリック | 試験本番形式の演習 |
| Cloze | 空欄を埋める | フリーテキスト or 想起のみ | 暗記、記述試験対策 |

**両者は補完関係**。同じ知識を MCQ でも cloze でも演習できる。Anki ユーザーは特に cloze を多用するため、Anki 互換性を考えると cloze サポートは戦略的に有意義。

### 採用判断（v1.x で検討）

#### 採用するケース

- F-104 で Anki .apkg インポート機能を実装する（cloze カードがそのまま入ってくる）
- ユーザーから「記述式・穴埋め問題も学習したい」要望が β / GA で多数
- 記述式回答が必要なドメインをターゲットにする

#### 採用しないケース

- ターゲットが完全に MCQ のみで cloze 不要（一部のドメイン）
- ユーザー要望が低い（β でフィードバック計測）

### 設計上の論点

#### 論点 1: cards テーブルの拡張 vs 別テーブル

**候補 (a)** cards.card_type カラム追加（'mcq' | 'cloze' | 'flashcard'）

```typescript
cards: {
  // 既存フィールド ...
  card_type: text('card_type').notNull().default('mcq'),  // 'mcq' | 'cloze' | 'flashcard'
  // mcq では options / correct_answer_ids 使用
  // cloze では question_text に Anki 記法 {{c1::答え}} を埋め込み、options は []
}
```

メリット: 1 テーブルで完結、フィルタや学習統計の集計が簡単
デメリット: スキーマに無駄なフィールドが増える

**候補 (b)** cloze 専用テーブル `cloze_cards` を新設

メリット: スキーマが綺麗
デメリット: 学習セッション・統計集計のクエリが複雑（UNION 必要）

**現状の判断**: **(a) が優位**。MVP の cards スキーマは cloze 拡張を阻害しない（question_text が Markdown text、options / correct_answer_ids が空配列で問題なし）。card_type カラムを v1.x で追加するだけで対応可。

#### 論点 2: 記法の互換性

Anki の `{{c1::答え::ヒント}}` 記法を採用するか独自記法にするか。

**候補 (a)** Anki 記法そのまま採用

メリット: Anki .apkg インポート時に変換不要、ユーザーの脳内モデル流用可、コミュニティ知識資産流用可
デメリット: なし

**候補 (b)** 独自記法（例: `[[blank:答え]]`）

メリット: なし
デメリット: 学習コスト、Anki インポート時に変換実装必要

**現状の判断**: **(a) Anki 記法採用**。実質一択。

#### 論点 3: 同番号統合 vs 別番号分割の UI

Anki の挙動（c1 統合、c2 分割）をそのまま採用するか、UI で「分割 / 統合」ボタンを設けるか。

**候補 (a)** Anki 挙動そのまま、UI に説明文を出すだけ
**候補 (b)** UI に「分割 / 統合」トグル、内部的には番号を自動管理

**現状の判断**: 実装時に決定。**(b) UI 化** がユーザーフレンドリーだが、Anki ユーザー向けには (a) の生記法サポートも欲しい。両方併用が無難。

#### 論点 4: AI 抽出における cloze 対応

Phase 0b 相当の OCR PoC を v1.x で再実施する際、AI に cloze 形式での出力を指示する選択肢が追加される。

例: 「医学教科書 PDF からポイントを抽出し、Anki cloze 形式で出力」

これにより MCQ では捉えにくい暗記項目（用語、数値、固有名詞）も自動取り込みできる。

### MVP への影響

**現状の MVP 設計は cloze 拡張に阻害的でない**ことを確認:

| 項目 | MVP 状態 | cloze 拡張時 |
|---|---|---|
| cards.question_text | Markdown text | `{{c1::答え}}` 記法を埋め込めば cloze として動作可 |
| cards.options | jsonb 配列 | cloze では空配列 `[]` で OK |
| cards.correct_answer_ids | jsonb 配列 | cloze では空配列 `[]` で OK |
| cards.card_type | 未追加 | v1.x で追加 |
| 学習エンジン | MCQ 専用 | v1.x で cloze モード追加 |

→ **MVP の cards スキーマは変更不要**。v1.x で `card_type` カラム追加 + 学習画面の cloze レンダラ実装で対応可。
